# Run MicroPython on your SoC

The LiteX port of [MicroPython](https://micropython.org/) lives in
[litex-hub/micropython](https://github.com/litex-hub/micropython) (`ports/litex`): a Python
REPL on the UART of any LiteX SoC with a supported CPU (RISC-V cores, Mor1kx, LM32), with
`umachine` basics (reset, frequency, identifier) and a `litex` module for the LEDs, switches
and the CSRs. By combining the flexibility of LiteX to define the hardware and the
flexibility of MicroPython to control it, very powerful and flexible systems can be created.

The port uses the software files generated by the target build (the hardware definition and
the register accessors), so the SoC is built first, then MicroPython against it.

### 1. Build the SoC

Any board of [LiteX-Boards](https://github.com/litex-hub/litex-boards), here the Arty with
GPIOs on a Pmod:

```sh
python3 -m litex_boards.targets.digilent_arty --with-ethernet --with-pmod-gpio --build --load
```

### 2. Build MicroPython for it

```sh
git clone https://github.com/litex-hub/micropython && cd micropython/ports/litex
export BUILD_DIRECTORY=<path to>/build/digilent_arty
make
```

### 3. Load it

```sh
litex_term /dev/ttyUSB1 --kernel=build/firmware.bin
```

or copy `build/firmware.bin` as `boot.bin` on the TFTP server / the SD card and let the
BIOS boot it ([Load application code](Load-Application-Code-To-CPU.md)).

```
>>> import litex
>>> litex.leds(0b0101)
>>> import umachine; umachine.freq()
```

### Notes

- The port is maintained in LiteX-Hub; the older [FuPy](https://fupy.github.io/) port
  (LM32, OpenRISC, 2018-2020) and the CircuitPython LiteX port (removed from CircuitPython in
  2021, it targeted the Fomu) are historical.
- MicroPython needs about 32 KiB of RAM and 128 KiB for the firmware: a block RAM main RAM is
  enough on mid-size FPGAs, otherwise a DRAM.
- [MQuickJS on LiteX](https://github.com/enjoy-digital/mquickjs-on-litex) does the same with
  JavaScript ([OSes ecosystem](OSes-Ecosystem.md)).
