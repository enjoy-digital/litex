# LiteX wiki diagrams

The diagrams of the [wiki](https://github.com/enjoy-digital/litex/wiki) are generated: one
script per diagram in this directory, written with [`litex_diagram.py`](litex_diagram.py), the
SVG in [`../wiki/images/`](../wiki/images/). The pages embed the SVG (small, text, diffable: no
binaries in the repository); `build.py --png` exports PNGs for posts and slides. The text is
Calibri/Carlito, with Arial/Liberation Sans as the fallback: the lint checks the labels fit with
both.

The style is the classic LiteX one: white canvas, chamfered boxes with a fine grey outline and a
soft shadow, light grey fills (darker for memories and hard blocks, `KEY` for the blocks the
diagram is about), grey orthogonal arrows (thick for data paths), Calibri/Carlito text, a caption
and the LiteX logo at the bottom. Same generator as the USB3-PIPE and TriXium diagrams.

```sh
sudo apt install fonts-crosextra-carlito fonts-liberation fonts-dejavu-core python3-pil   # Carlito = Calibri metrics
python3 doc/diagrams/build.py                 # SVGs + lint
python3 doc/diagrams/build.py --only NAME     # one diagram
python3 doc/diagrams/build.py --check         # what CI runs: SVGs up to date, lint clean
python3 doc/diagrams/build.py --png           # + PNGs in doc/diagrams/build/ (needs Inkscape, not committed)
python3 doc/diagrams/svglint.py doc/wiki/images/NAME.svg -v   # lists the widest labels
```

## Adding or editing a diagram

1. Copy the closest existing script to `doc/diagrams/<name>.py` (`<name>` lowercase, hyphens,
   `litex-` prefix for the generic LiteX ones), add `<name>` (with its PNG export width, about
   twice the canvas width) to `DIAGRAMS` in `build.py`.
2. Lay it out on a grid: columns of boxes share their x edges, rows share their centre lines,
   arrows leave and enter boxes at their centre lines and turn at right angles, a junction dot
   where a route branches (no arrow head at the junction). Keep the labels short: a bold title
   and one or two 13 px lines per box.
3. `python3 doc/diagrams/build.py --only <name>`: the lint must report `0 issue(s)` with both
   fonts (labels crossing or within 4 px of an edge, an arrow or another label). Open the SVG in
   a browser at about 900 px wide, the width of a wiki page.
4. Embed it in the page: `![<alt text>](images/<name>.svg)` followed by a line
   `*<caption>* (generated by `doc/diagrams/<name>.py`)`.
5. Commit the script and the SVG. `build.py --check` in CI fails when the SVG does not match
   its script.

The SVG stays editable by hand (Inkscape or XML) for a quick fix, but the script is the source:
port the change back before committing, or `--check` will flag the difference.

## Terminal captures and timing diagrams

Two helpers draw the other pictures the pages need, in the same style and with the same checks:

- [`terminal.py`](terminal.py): a terminal session as a dark box of monospace text. The text
  lives in [`captures/<name>.txt`](captures/) (about 25 lines, the box hugs the longest one, an `...` line where
  output is skipped; freeze what changes from run to run: dates, hashes, timings) and the script
  is a few lines: `LINES = capture("name")`, `COLS = Terminal.fit(LINES)`,
  `W, H = Terminal.size(LINES, cols=COLS, caption=(TITLE, SUBTITLE))`,
  `Terminal(d, cols=COLS).draw_centered(W, 24, LINES)`, then the caption and the footer. See
  [`litex-sim-boot.py`](litex-sim-boot.py). Lines starting with a prompt (`$ `, `litex> `) are bold.
- [`wave.py`](wave.py): a timing diagram from the transitions written in the script:
  `Wave(d, x, y, cycles=10).clock("sys_clk").bit("we", "0010000000").bus("adr", {2: "0x04", 3: None})`.
  See [`litex-csr-wave.py`](litex-csr-wave.py).

Monospace text uses Liberation Mono (Cousine and DejaVu Sans Mono have the same width, the lint
measures with Liberation Mono and DejaVu Sans Mono); a capture is a text file, not a screenshot,
so it is diffable, reviewable and a few KB.
